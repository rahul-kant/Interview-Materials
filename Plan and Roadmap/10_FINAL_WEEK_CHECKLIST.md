# Final Week Checklist - Interview Ready

## Overview
You've spent months preparing. This is your final week before interviews start. This checklist ensures you're at peak readiness while avoiding burnout.

**Goal**: Consolidate knowledge, boost confidence, stay sharp without overloading.

---

## General Principles for Final Week

### ✅ DO:
- Light review of concepts
- Practice 1-2 problems daily (stay sharp)
- Review your notes and patterns
- Polish behavioral stories
- Get good sleep (8 hours minimum)
- Exercise and stay healthy
- Maintain routine
- Stay confident

### ❌ DON'T:
- Learn new topics
- Solve 10 problems/day (burnout risk)
- Pull all-nighters
- Panic if you can't solve a problem
- Skip meals or exercise
- Over-caffeinate
- Cram the night before
- Second-guess your preparation

## Cheat Sheets to Review

### Coding Interview Cheat Sheet

**Arrays & Strings:**
- Two pointers: O(n) time, O(1) space
- Sliding window: O(n) time
- Hash map for frequency: O(n) time, O(n) space

**Trees:**
- DFS traversal: O(n) time, O(h) space
- BFS level-order: O(n) time, O(w) space
- BST operations: O(log n) average

**Graphs:**
- BFS: O(V+E) time, O(V) space
- DFS: O(V+E) time, O(V) space
- Dijkstra: O((V+E) log V) with min heap
- Union-Find: O(α(n)) ≈ O(1) per operation

**Dynamic Programming:**
- 1D DP: O(n) time, O(n) or O(1) space
- 2D DP: O(m*n) time, O(m*n) or O(n) space
- Identify: Optimal substructure + overlapping subproblems

**Binary Search:**
- Sorted array: O(log n) time
- Template: while (left <= right)
- Result patterns: first/last occurrence, closest value

### System Design Cheat Sheet

**Framework:**
1. Requirements (5 mins)
2. Estimation (5 mins)
3. API Design (5 mins)
4. High-Level Design (10 mins)
5. Deep Dive (20 mins)
6. Trade-offs (5 mins)

**Key Components:**
- Load Balancer (L4/L7)
- Cache (Redis, Memcached)
- Database (SQL vs NoSQL)
- Message Queue (Kafka, RabbitMQ)
- CDN (CloudFront, Akamai)
- Object Storage (S3)

**Scalability Patterns:**
- Horizontal scaling (add servers)
- Vertical scaling (bigger servers)
- Database replication (master-slave)
- Database sharding (partition data)
- Caching (multiple levels)
- Asynchronous processing (queues)

**Numbers to Remember:**
- 1 million = 10^6
- 1 billion = 10^9
- 1 day = 86,400 seconds ≈ 10^5
- 1 GB = 10^9 bytes
- Average request size: 1KB
- QPS for 1M DAU: ~10-100

## Common Mistakes to Avoid

### Technical Interviews
- ❌ Jumping into code without clarifying
- ❌ Not thinking out loud
- ❌ Ignoring hints from interviewer
- ❌ Not testing your code
- ❌ Giving up too quickly
- ❌ Overcomplicating simple problems

### System Design
- ❌ Not asking clarifying questions
- ❌ Skipping requirements gathering
- ❌ Jumping to implementation details
- ❌ Not discussing trade-offs
- ❌ Designing for day 1 instead of scale
- ❌ Not leading the discussion

### Behavioral
- ❌ Not using STAR format
- ❌ Being too vague (no metrics)
- ❌ Rambling (>8 mins per story)
- ❌ Blaming others
- ❌ Not showing learning from failures
- ❌ Sounding rehearsed/robotic

## Emergency Protocols

### Technical Difficulties
**If internet drops:**
1. Quickly switch to mobile hotspot
2. Text/call recruiter immediately
3. Rejoin meeting ASAP
4. Stay calm, apologize briefly, continue

**If software crashes:**
1. Have backup device ready
2. Rejoin on backup device
3. Inform interviewer calmly
4. Continue from where you left off

**If you can't hear interviewer:**
1. Politely ask them to repeat
2. Check audio settings
3. Ask to use chat if needed
4. Stay professional

### If You're Stuck on Problem
1. **Don't panic** - It's normal
2. **Think out loud** - Show your process
3. **Ask clarifying questions**
4. **Start with brute force**
5. **Take hints graciously**
6. **Work through examples**
7. **Break down the problem**

### If Running Out of Time
1. **State your approach clearly**
2. **Outline remaining steps**
3. **Discuss time/space complexity**
4. **Mention edge cases**
5. **Ask if they want you to code or discuss**
